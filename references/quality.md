# 验收与修订

制作前核查故事主线、事实来源、画面覆盖和时长预算。未知资料不能靠生成历史画面补齐。按实际配音长度计算时长，不用字数估计代替最终计时。

`studio.py verify` 检查主轨连续、媒体存在、字幕不重叠/越界、原生字幕与公共时间轴一致、帧数/尺寸/时长、黑屏区间、重复底图及字体路径，生成抽帧图和报告。报告不能宣称已核实每张图片史实或验证 GUI。

Agent 还需检查：

- 字幕完整保留旁白含义，人名、词语、短主语不能被机械拆开。句末是硬边界，“七月”等下一句短语不能接到上一句。句内也按完整意思切分，不能因短分句自动合并，把“叫糖”接到下一条“黄金不叫黄金”前。对照、暗号、引语和短判断逐条复核，必要时用 editorial_cuts 明确边界；修改后拼接的去标点正文必须完整一致。
- 用户要求保留的引号须在公共字幕列表、ASS/SRT、实际成片和必剪原生文字中一致存在；核对同一关键词的所有出现处。默认清理标点的工具可能吞掉引号，须在项目的生成逻辑中显式处理，不能只补一份SRT。语义完整性校验可忽略展示引号，实际展示不能因此丢失引号。
- 字幕与标题不能出画、挡关键物体或压住报刊标题。日期标识在进入不相关事件画面前结束。
- 新字幕的原生黑色描边覆盖所有语言和说明层，粗细10/100；核对开关、不透明黑色与非零宽度三者，不能只检查drawOutline。选白色手稿、浅色地图、亮天空及小画幅预览检查，不能仅在暗色画面确认可读。本地ASS与必剪直接导出分开验证，详见[原生字幕描边](production.md#原生字幕描边)。
- 相同内容的不同清晰度文件可能不同哈希，须借助 provenance_id 按同图合计。
- 片尾不突然引入未展开的新例子；理论由故事中的行动与结果接过去，避免逐项“体现”排比。
- 配乐不盖住人声，切换和结尾自然收束；无配乐版确实不含音乐。既检查峰值上限，也检查实际综合响度与人声/音乐相对音量，不能把整体过轻当作通过。`loudnorm`诊断中的输出预测值不代表文件已归一化，应读取待交付文件的实际输入测量值；能听时实际抽听。
- 历史片检查是否主动寻找影像、原声和访谈，不为方便默认全部照片。原声字幕对实际发言，旁白让出空间，身份年代可辨；声音跨镜头不造成口型错位、双重原声或含义改变。
- 演讲片找到可用本人讲话录像时，检查首15秒内本人实际讲话至少5秒；按[片头本人讲话与选材优先级](original-audio.md#片头本人讲话与选材优先级)记录出镜区间并核算，实际看首15秒与切点。正文按语义蒙太奇验收，仅在有对应原句且动作可辨的讲话录像时按需切回本人，不能强制让关键句回到静止人像；排查同一讲话机位及照片长期重复停留；后段出镜再多也不能替代片头要求，尚未满足时如实报告。
- 检查实际画面组织而非只数工程片段：列出正文的语义段落与对应历史镜头，复看长时间现场讲话、静态人像和连续同机位区间。按20秒分段或原片自带剪辑不等于新蒙太奇；来源、字幕和文件检查通过不能代替剪辑节奏验收。
- 对最终MP4逐声道测量电平、峰值与有声覆盖，并检查开头、正文、转场和结尾；声道数标注为2不证明两侧有有效声音。有效历史录音只在一侧、另一侧只有底噪时，使用有效声道生成双侧同声，不能放大空声道噪声；真实立体声保留合理差异，不为追求数值相同强行合并。
- 历史演讲系列常规目标约−16 LUFS、真峰值不高于−1.5 dBTP；记录最终文件实际测量值，避免削波、响度突变和配乐盖讲话。只改画面时保留已修复并确认的音轨，尤其不能回退到仅左声道的旧源；修复声音后同步更新MP4、必剪独立音轨、重建源及交付说明。
- 分段音乐契合叙事，换曲不突兀，留白有目的；原片音乐不与新音乐冲突，热门 BGM 确认曲名、版本和使用条件。

先改 job 的事实、文案或镜头，再生成公共时间轴、ASS/SRT、成片和原生工程；修改后重新验收，不能用旧报告证明新版本。

声音缓存键包含正文、音色和合成参数。镜头缓存键包含素材内容哈希、裁切/焦点、帧数、画幅与渲染器版本。ASS 必须在烧字幕之前生成，原生字幕从同一列表生成，不按“文件存在”跳过过期内容。

项目自行预裁切的中间片也必须用源文件哈希、原片入出点、校准倍率及输出帧数生成缓存键，不能只用“001.mp4”加文件存在判断。改选源片后，即便时长相同也可能误用旧画面；复用前同时核对选段映射和实际帧数。最终镜头缓存正确不能修复其上游已经过期的中间片。

词时序须覆盖完整旁白，非空音频也可能被云服务截断。检查人名、书名及短主语的字幕组合；“毛泽东”“朱德”等不能因顿号机械拆成孤立闪现。复用照片运镜 MP4 仍按原底图计数；真实动态片段不能为新时长默认加速播放。需要转写核对或参考表达时见 [参考文案与表达改写](reference-style.md)。

已认可版本在原目录保留；后续改版用新输出目录。迁移测试复制整个交付目录到不同路径后重定位，检查原路径不再被引用。实际跨电脑/版本打开是独立验证级别。

## 修订时同时满足已确认要求

将用户的新反馈与仍有效的既有要求一起验收。例如“原序不变”“开头本人讲话”“保留指定原图封面”须同时成立；不能修好词序却退回无人出镜的片头。若素材确实不能同时满足，应说明缺少什么素材，不将其中一个要求当作已取消。

镜头修改先检查受影响区间的首帧、说话时刻及切点前后，再检查全片；全片四分点抽帧可能完全漏掉片头问题。本人出镜应以实际镜头覆盖为依据，不能把整段原视频的时长全算成本人近景。需要方便用户复核时，附短预览并同时交付完整修改版。

重复视频检查按共同原片id及原始时间范围进行，不仅比较成片片段的文件名或哈希。`verify`报告可追溯的区间重叠及reuse_reason；未说明的重叠须人工处理或解释，不能当作已无重复。两个汇编片也可能共用底片，需用抽帧／相邻切点复查。区间不重叠也不等于视觉内容不重复，反复用相似动作或同一机位仍应按观感调整。

对照公共时间轴和原生工程，确认画面替换没有移动声音、字幕或后续镜头的时间；声音保留的证据见[完整原声与双语字幕](original-audio.md)。每次改动后刷新与当前媒体匹配的验收报告，最后再登记和打包，避免压缩包携带旧版检查结果或字幕。

## 从样板扩展到全片

用户已确认的短样板作为本次改版依据。将其镜头顺序、实际持续时间、裁切和运镜、文字内容、字体字号位置、字幕层级一起应用到全片；不要只换首图后遗失背景介绍或重新引入已删除标题。用户要求背景集中在第一张图时，各句可用独立层同时显示，结束点跟随该镜头，不能延续压到后续画面；这属于当前请求，不默认所有片头都加大段介绍。

扩展后检查样板范围内的公共时间轴和原生文字，再在首帧、镜头切点前后和字幕出现处对比实际抽帧。编码参数相同可比较像素；编码条件不同应容许压缩差异，不能把视频文件哈希不一致直接认定为内容不同。全片另外确认总帧数、后半段字幕与声音结尾，短样板通过不替代全片验收。原声完整性与双语对齐见 [完整原声与双语字幕](original-audio.md)。

模板已在必剪 Windows 3.11.25 中使用并经用户验证。路径重建可自动测试；未知必剪版本、竖屏或其他分辨率的原生显示仍需当前版本样板/实际打开验证，不能仅因 JSON 可解析就承诺兼容。

## 用户审核与既有稿件换源

用户指定先审核再提交时，完成本地改版、全片审看MP4、可编辑工程及所需双比例封面后交给用户审核。没有用户对本版的明确通过与提交授权，不上传或提交B站修改；制作完成、技术检查通过或上一版已获发布授权不能替代这次审核。

获得换源授权后编辑原稿，沿用原BV号。先读取远端当前文案、双封面、知识分区、合集和其他设置，保留用户手动修改；回读新视频源及应保留字段，不为改画面或声音重新发布重复稿件。上传、提交、审核中及审核通过分别报告。
